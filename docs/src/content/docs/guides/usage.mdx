## Default view

```bash
workfold [PATH ...]
```

With no path, Workfold uses `.`. For Git collection, a path selects its entire
containing repository, not a history pathspec. Multiple paths in the same
repository are deduplicated. If the selected path is not in a repository, use
`-m fs` or pass a repository path.

The default view selects:

- the current ISO week in the resolved local timezone;
- the `standard` evidence preset;
- Git commit records reachable through local branches plus a detached `HEAD`;
- author timestamps from every recorded Git identity;
- `Mo-Fr 08:00-16:30` as the working schedule;
- a `1h` sparse cluster window anchored at events;
- range labels for occupied time bands.

`-m/--mode` selects `git`, `fs`, or `both` and defaults to `git`. It is
independent from `-t/--time`: changing one never changes the other.

Git collection invokes the local `git` executable and never fetches or contacts
a remote. Use `--git-commits-from head` to limit history to the currently
checked-out branch or detached `HEAD`.

## Configuration files

Workfold can load personal and project defaults without changing the meaning of
its CLI flags. Resolution is deterministic:

```text
built-in → global config → nearest project config → explicit CLI
```

Each layer overrides only the keys it contains. Arrays replace earlier arrays;
they are not concatenated. Unknown keys, wrong TOML types, malformed values,
and invalid final option combinations are usage errors rather than silently
ignored settings.

The automatic global file is platform-specific:

| Platform | Location |
| --- | --- |
| Linux and other Unix | `${XDG_CONFIG_HOME:-~/.config}/workfold/workfold.toml` |
| macOS | `~/Library/Application Support/workfold/workfold.toml` |
| Windows | `%APPDATA%\workfold\workfold.toml` |

Starting at each selected `PATH`, Workfold searches upward for the nearest
`workfold.toml` or a `pyproject.toml` containing `[tool.workfold]`. A standalone
`workfold.toml` wins if both exist in the same directory. Multiple input paths
must resolve to the same project configuration because one chart has one
timezone, schedule, and rendering policy; otherwise Workfold asks for an
explicit choice.

A standalone file stores keys at its root:

```toml title="workfold.toml"
time = "this-week"
mode = "git"
profile = "standard"

timezone = "Europe/Berlin"
hours = "Mo-Thu 08:00-16:30; Fr 08:00-14:00"
cluster-window = "1h"
cluster-anchor = "event"
band-label = "range"
show-empty-bands = false
marker-style = "identity"
grid = "vertical"
hide-empty-days = ["weekend"]
```

The same settings fit inside a Python project file:

```toml title="pyproject.toml"
[tool.workfold]
timezone = "Europe/Berlin"
hours = "Mo-Fr 08:00-16:30"
grid = "vertical"
```

Repeatable and multi-value CLI selections use TOML arrays. `time` also accepts
one string for its common single-selector form:

```toml
mode = "both"
time = ["2026-W30", "2026-W31"]
git-identity = ["jan@example.com", "Jan Müller"]
fs-exclude = ["node_modules", "*.log"]
hide-days = []
hide-empty-days = ["weekend"]
list = ["outside"]
```

For exact event selection, use `events` instead of `mode` and `profile` in that
layer:

```toml
events = ["git:commit:committer", "git:tag:tagger", "fs:file:modified"]
list = ["outside", "git:tag:tagger"]
```

`events` is a complete alternative to the mode/profile preset pair. Defining
both styles in one precedence layer is an error. A higher-precedence `events`
setting replaces a lower mode/profile choice; a higher-precedence mode or
profile replaces lower custom events. Git-only and filesystem-only non-event
keys must agree with the resulting event sources.

Other configurable keys are `git-commits-from`, `include-ignored`, `fs-exclude`,
`cluster-anchor`, `band-label`, `show-empty-bands`, `display-hours`, `no-color`,
`list`, `limit`, `coverage`, `strict`, and `verbose`. Boolean values use
TOML `true`/`false`. Positional paths and the configuration-control flags
themselves are deliberately not configurable.
`no-color = false` restores the same automatic terminal detection used by
default; neither it nor `--color` overrides `NO_COLOR` or terminal detection.
`--no-show-empty-bands` can temporarily override a configured
`show-empty-bands = true` without disabling the rest of the configuration.
Use `timezone = "local"` for the operating-system local zone and
`display-hours = "auto"` for an automatic chart range; these values can also
reset a global setting from a nearer layer. Omit `git-commits-from` for the
selected profile's default.

The locked `portable` and `full` profiles keep their CLI semantics. A
higher-precedence profile replaces custom events and policy defaults inherited
from a lower layer. Reachability and ignore-policy settings
that would redefine a locked profile are rejected at the same or a higher
layer.

Inspect the fully validated result without collecting Git or filesystem data:

```bash
workfold . --show-config
workfold . --grid both --show-config  # includes this CLI override and its origin
```

`--show-config` prints the loaded files followed by every effective value and
whether it came from a built-in, global file, local file, exact config file, or
the CLI. Derived values identify every controlling setting, while values reset
by a higher-precedence source or profile identify that decision. The table
wraps to the terminal width. `--help` remains stable and describes built-in
defaults; it does not pretend configured values are universal defaults.

Use one exact file and disable automatic global/project discovery with
`--config FILE`. An explicitly named `pyproject.toml` still reads
`[tool.workfold]`; any other filename uses the standalone root schema. Use
`--no-config` for built-ins plus CLI only:

```bash
workfold . --config ~/workfold/client.toml
workfold . --no-config
```

## Select dates

`-t/--time` defaults to `this-week` and accepts one selector kind at a time:

```bash
# One ISO week, or a union of repeated weeks
workfold . -t 2026-W31
workfold . -t 2026-W30 -t 2026-W31

# Inclusive local calendar dates; either endpoint may be open
workfold . -t 2026-07-01..2026-07-31
workfold . -t 2026-01-01..
workfold . -t ..2026-07-31

# A rolling elapsed window ending when this run starts
workfold . -t 2w
workfold . -t 2w3d
workfold . -t 6h30m

# Every available date for the otherwise selected mode/evidence scope
workfold . -t all
```

`this-week`, ranges, and `all` occur once. Repetition is reserved for ISO weeks;
mixing selector kinds is invalid. All selected dates still fold onto one
Monday-to-Sunday chart. Internally, Workfold converts inclusive calendar choices
to half-open instant ranges so a boundary event is not counted twice.

Rolling selectors are also single-use and form the half-open instant range
`[captured-now - duration, captured-now)`. Workfold captures `now` once for the
run. Components use ordered, nonrepeating `w`, `d`, `h`, and `m` units;
`w` is seven elapsed 24-hour days, `d` is 24 elapsed hours, and `m` means
minutes. This fixed-duration behavior remains exact across daylight-saving
changes. Calendar months are intentionally not accepted because their length
and boundary semantics differ from elapsed durations.

## Configure timezone and schedule

Events are converted into the selected IANA timezone before weekday, clock
time, and schedule classification are derived. This preserves daylight-saving
rules.

```bash
workfold . --timezone Europe/Berlin
workfold . --hours 'Mo-Fr 08:00-16:30'
workfold . --hours 'Mo-Thu 08:00-16:30; Fr 08:00-14:00'
workfold . --hours 'Mo-Fr 08:00-12:00,13:00-16:30'
workfold . --hours all
```

Schedule intervals are half-open: the start is inside and the end is outside.
A weekday accepts either Workfold's two-letter token (`Mo`, `Th`) or its common
three-letter English alias (`Mon`, `Thu`), case-insensitively. Output is
normalized to the two-letter form.
A weekday with no interval is entirely outside. Overnight intervals are not in
the MVP; express the two sides as clauses on adjacent days.
`all` is a compact seven-day `00:00-24:00` schedule: every selected event is
inside working hours, including weekend events. It changes classification only;
it does not select more dates, enable sources, or force empty chart rows.

## Read and tune the chart

By default, the chart renders only occupied bands in implicit
`00:00`-toward-`24:00` order and compresses empty time. Workfold sorts visible
events by localized wall-clock time and shares every band across all visible
weekday columns.

`--cluster-anchor event` is the default. It uses the earliest unassigned event
as the next anchor, assigns events in `[anchor, anchor + cluster-window)`, and
repeats. The anchor never moves when a later event joins the band.

`--cluster-anchor midnight` uses fixed local-clock intervals starting at
`00:00`. With `--cluster-window 1h`, the bands are `[00:00,01:00)`,
`[01:00,02:00)`, and so on. An event exactly on an endpoint belongs to the next
band. Its window must be a whole number of minutes so fixed `HH:MM` labels show
their exact boundaries. If a custom window does not divide 24 hours evenly, the
last interval is clipped at `24:00` and the next weekday starts from `00:00`
again.

`--band-label range` is independent from anchoring and remains the default.
Event-anchored range labels show the first through last visible event, preserving
the current compact extent view; midnight-anchored range labels show the fixed
interval bounds. `--band-label start` prints only the band start and includes
the compact `Time` heading. Endpoint labels use
minute-level `HH:MM` text. An event-anchored label names the minute containing
its exact observation or anchor; because the minimum window is one minute,
distinct clusters cannot receive the same minute-only start label. Exact
seconds and nanoseconds remain in normalized provenance and exact listed-event
rows.

`--cluster-window` accepts a duration from `1m` up to, but not including, 24
hours. Components use
`h`, `m`, and `s` in that order without repeating a unit. Whitespace is optional
between complete components, but a spaced value must be quoted as one CLI
argument. Second components are available with event anchoring; midnight
anchoring requires a whole-minute result. The default is `1h`; smaller values
such as `1m30s` and `10m` are custom views:

```bash
workfold . --cluster-window 1m30s --cluster-anchor event
workfold . --cluster-window 10m
workfold . --cluster-window 1h
workfold . --cluster-window 1h5m --cluster-anchor midnight
workfold . --cluster-window '1h 5m'
workfold . --cluster-anchor event
workfold . --cluster-anchor midnight --show-empty-bands
workfold . --band-label range
workfold . --band-label start
```

Internal grid lines are optional:

```bash
workfold . --grid none        # default
workfold . --grid vertical
workfold . --grid horizontal
workfold . --grid both
```

Vertical lines separate the time band from each visible weekday column.
Horizontal lines appear below the header and between logical time clusters;
they never split a wrapped continuation row. When clusters have a compressed
gap, its `⋮` duration is embedded into their shared boundary instead of becoming
a separate row. Grid styles use dim internal lines without an outer box.

Weekday columns are independently controllable without filtering the event
scope:

```bash
workfold . -E all
workfold . -H weekend
workfold . --hide-empty-days weekend
workfold . --hide-empty-days weekdays
workfold . --hide-empty-days mon,wed,sunday
workfold . --hide-days weekend --hide-empty-days weekdays
```

`-H` is short for `--hide-days`; `-E` is short for `--hide-empty-days`. Both
options are repeatable and accept comma-separated, case-insensitive
two-letter, three-letter, or full weekday names plus the `weekdays` and
`weekend` groups. `--hide-empty-days` also accepts `all`. Empty means no marker
remains in that column after selection and `--display-hours` cropping. An
occupied day is therefore always preserved by `--hide-empty-days`.

`--hide-days` is unconditional. Its events disappear from the matrix but remain
in Events, Schedule, Calendar, coverage, and `--list`; a compact
`Hidden` line accounts for occupied columns. Empty-column hiding needs no such
notice because it omits no visible event. Column projection happens before
clustering, so hidden weekdays cannot anchor or stretch a visible time band.

Events are ordered by local wall time, actual instant, canonical source (Git
before filesystem for simultaneous ties), and stable marker ID; weekdays only
group those events into columns. Each ordinary event is a symbol: Git uses
circles, filesystem uses squares,
inside-hours markers are filled, and outside-hours markers are hollow. Color
adds green for inside-hours Git, blue for inside-hours filesystem, and red for
outside-hours events. If a cell is too busy for individual symbols at the
available width, exact tokens such as `●×12 ■×4 ○×2` replace only that
cell; they are counts, not density estimates. Empty bands are omitted by
default. With event anchoring, a gap cue measures consecutive observed extents;
with midnight anchoring, it measures wholly omitted fixed intervals. A gap of
at least one configured cluster window gets one dim duration cue. Consequently,
one omitted fixed band is enough under midnight anchoring, while a shorter
event-to-event gap remains implicit under event anchoring. Second-based event
windows retain seconds in a displayed gap duration even though clock labels use
minute-level `HH:MM` text.

Use `--show-empty-bands` to replace sparse gap compression with every fixed
interval in the resolved display range:

```bash
workfold . --cluster-anchor midnight --show-empty-bands
workfold . --cluster-anchor midnight --show-empty-bands --display-hours 06:30-20:15
```

The option requires midnight anchoring. Event-anchored bands begin at events,
so an empty event-anchored band has no truthful anchor; combining the option
with `--cluster-anchor event` is therefore a usage error rather than an ignored
request. When an explicit display crop cuts through a fixed interval, the
first or last displayed label is clipped to the requested boundary while event
membership retains its original midnight-aligned half-open band. Automatic
display ranges instead expand outward to complete fixed bands, so start-only
labels always name their real midnight anchor. Under an explicit crop, a
partial edge shows its exact range even with `--band-label start`. Dense mode
does not print `⋮` cues, change event counts, or alter coverage.

Use `--marker-style identity` when contributor recognition matters more than a
single Git source symbol:

```bash
workfold . -t 2w --marker-style identity
```

Each visible Git marker then uses a deterministic code derived from the exact
recorded name/email pair. The key maps every visible code back to that full,
unverified Git identity exactly once, using its canonical uppercase code in
green. It never adds a lowercase entry for each identity; the single red `a–z`
outside-hours cue explains every lowercase occurrence compactly.
An identity uses the first ASCII letter in its normalized name, then its email
as a fallback, and `I` if neither contains one. A unique initial remains one
letter; every member of a shared initial group is numbered from `1`, such as
`J1`, `J2`, and `J3`. This remains unbounded and adjacent markers are
self-delimiting without spaces: `J1J2j3` is two inside-hours identities followed
by the outside-hours form of `J3`.
When one marker coalesces identical author and committer instants belonging to
different identities, it receives `◆` (then `◆2`, `◆3`, if several such
groups are visible) rather than arbitrarily choosing one person. Filesystem
markers remain squares. In every color mode, uppercase/lowercase identity codes
mean inside/outside; composite codes use `◆`/`◇` for the same distinction.

Terminal output starts directly with the matrix; there is no title or context
subtitle above it. A content-aware symbol key follows without a heading. It
names only categories actually visible after display cropping and explains
`×N` only when exact-count tokens occur. One conditional outside-hours cue uses
the hollow shapes or lowercase classes actually present; the entire cue is red
when color is available. It never repeats one contributor's marker as a global
example. The configured schedule follows on an independent left-aligned
`Working hours:` line. Three statistic rows then appear without a Summary
heading: Events is the common total, Schedule is its
inside/outside split, and Calendar is its independent weekday/weekend split.
Both split rows show counts and percentages of Events; a weekend event can also
be outside the schedule. Use `--verbose` for scope, period, the complete successful
coverage wording, source/record breakdowns, cluster/compression policy, exact
collector selection, Git identity scope, collection extents, ignore/exclusion
policy, and the detailed coverage ledger. Use `--coverage` for the ledger
without those verbose details. Partial collection, explicit narrowing,
unsupported capabilities, and nonzero cropping remain visible by default as
exception notices.

`--display-hours` crops chart rows only. It does not change classification:

```bash
workfold . --hours 'Mo-Fr 08:00-16:30' --display-hours '06:00-22:00'
```

A compact notice after the summary reports nonzero event counts hidden before or
at/after an explicit half-open crop; zero-valued crop notices are omitted.
Cropping happens before clustering and the requested bounds are not rounded, so
a marker at the start is visible and one exactly at the end is hidden. Cropping
does not realign midnight-anchored interval boundaries.

## Select exact event evidence

Mode and profile provide the common presets. `-e/--events` is the exact
alternative when a preset is not the question you want to ask:

```bash
workfold . --events git:commit:author
workfold . --events git:commit:committer git:tag:tagger
workfold . --events git:file-change:author fs:file:modified
workfold . --events 'git:*:committer'
workfold . --events 'fs:*'
workfold . --events '*'
```

The supported identifiers are:

| Identifier | Evidence |
| --- | --- |
| `git:commit:author` | commit author timestamp |
| `git:commit:committer` | commit committer timestamp |
| `git:file-change:author` | one derived file-change marker at its commit's author time |
| `git:file-change:committer` | one derived file-change marker at its commit's committer time |
| `git:tag:tagger` | annotated-tag tagger timestamp |
| `git:reflog:update` | local ref-update timestamp recorded in a reflog |
| `fs:file:<timestamp>` | current regular-file metadata timestamp |
| `fs:directory:<timestamp>` | current directory metadata timestamp |
| `fs:symlink:<timestamp>` | current symlink metadata timestamp, without following its target |

Every filesystem selector replaces `<timestamp>` with `birth`, `modified`,
`metadata-changed`, or `accessed`. Exact examples include `fs:file:modified`,
`fs:directory:birth`, and `fs:symlink:accessed`.

Several values form a union and can follow one `--events`; repeating the option
also extends that union. Each `*` token is matched against the complete canonical
identifiers, so `git:*`, `git:commit:*`, `git:*:committer`, `fs:file:*`,
`fs:*:modified`, `fs:*`, and `*` are useful scopes.
Quote wildcard selectors to prevent shell pathname expansion. Identifiers are
case-insensitive and output is normalized to the lower-case forms above.

`--events` cannot be combined with `-m/--mode` or `-p/--profile` in the same
CLI invocation because it already defines both source and event kind. It does
not replace independent controls such as `--git-commits-from`, `--git-identity`,
ignore policy, or `--fs-exclude`. Consequently `--events '*'`
selects every timestamp event kind but is not identical to `-m both -p full`:
the custom form retains ordinary local-branch reachability and the
ignore-respecting filesystem policy unless those axes are changed explicitly.

Because `--events` and `--list` accept one or more whitespace-separated values,
put every positional `PATH` before either option.

## Inspect Git evidence

Git event kind, timestamp role, reachability, and identity are independently
controllable:

```bash
workfold . --events git:commit:author
workfold . --events git:commit:committer
workfold . --events git:commit:author git:commit:committer
workfold . --events git:file-change:author
workfold . --events git:file-change:committer
workfold . --events git:tag:tagger git:reflog:update
workfold . --git-commits-from head
workfold . --git-commits-from local-branches
workfold . --git-commits-from all-refs
workfold . --git-identity 'Ada' --git-identity 'ada@example.com'
```

Commit reachability has three explicit scopes:

- `head` follows the ancestry of the currently checked-out branch or detached
  `HEAD`;
- `local-branches` follows every `refs/heads/*` branch and also includes a
  detached `HEAD`; this is the standard default;
- `all-refs` follows every locally stored ref, including remote-tracking refs,
  tags, stash, and custom refs; it never fetches and is the portable/full
  default.

A commit is considered once by object ID even when several selected refs reach
it. Reachability is established before timestamp-role selection. Each requested
author or committer role is then matched independently, so a reachable commit
can contribute its author event, committer event, both, or neither. For bounded
queries Workfold may apply that exact predicate during its lightweight revision
scan; known non-matching values are outside the query rather than reported as
filtered coverage outcomes. Ordinary `git --since` is not used for author-date
selection because author timestamps are not ordered by commit topology.

Commit and file-change roles are separate selectors: a request may show commit
author events while deriving file changes only at committer times. File-change
observations inherit the matching timestamp role and identity of their commit.
Workfold derives commit-versus-parent tree differences only for commits with at
least one matching role, producing the same result as deriving every reachable
change and filtering afterward. Commits known only to an unfetched remote or no
longer reachable from the selected refs are outside the commit scope. A full
profile can still expose a local reflog timestamp referring to an otherwise
unreachable commit, but that reflog observation is not converted into a commit
observation.

`--git-identity` is an inclusive filter over the identity attached to each Git
timestamp: an author observation uses its author, a committer observation its
committer, an annotated-tag observation its tagger, and a reflog observation its
reflog actor. File-change observations inherit the corresponding author or
committer identity from their commit. Matching is a case-insensitive literal
substring of the recorded name or email. Repeated values use OR semantics; with
no flag, all recorded Git identities are included. Git identities are
self-declared metadata, not verified people or accounts. In combined mode the
filter does not affect filesystem observations.

Identity selection happens before plotting. Therefore, when identical author and
committer instants could share one marker, only the matching role remains if
their identities differ; both roles remain when both match. Lightweight tags
have no independent tagger timestamp or tagger identity and therefore produce
no tag observation, as reported by coverage.

Annotated tags carry tagger timestamps; lightweight tags have no independent
tagger time. Reflogs are local and may be disabled or expired. Git stores tree
snapshots, not human file-change actions: Workfold derives each change from the
commit-versus-first-parent tree difference (or root-versus-empty tree), uses
Git's reported change kind, and preserves renames when Git reports one.

## Inspect filesystem evidence

Filesystem mode scans current metadata rather than reconstructing editing
history:

```bash
workfold . --events fs:file:birth fs:file:modified
workfold . --events fs:directory:metadata-changed fs:symlink:accessed
workfold . --events 'fs:*:modified'
workfold . --events 'fs:directory:*'
workfold . -m fs -p full
workfold . -m both
```

Timestamp labels are deliberately precise:

- `birth` uses a real birth/creation time only where available; on Linux,
  Workfold requests `STATX_BTIME` through `statx`;
- `modified` is mtime;
- `metadata-changed` is POSIX metadata-change ctime, never creation time;
- `accessed` is atime and is labeled potentially unreliable.

The standard filesystem preset selects birth and modification timestamps for
regular files. Exact selectors make entry type and timestamp role independent:
`fs:*:modified` requests mtime for files, directories, and symlinks, while
`fs:directory:*` requests every supported timestamp only for directories.
Symlink targets are not followed, including by Linux birth-time reads, and raw
`.git/` internals are always excluded. A filesystem that does not return birth
time is reported as unavailable rather than receiving a fabricated ctime value.
In a Git worktree, standard Git ignore semantics are respected by default:

```bash
workfold . -m fs --respect-gitignore
workfold . -m fs --include-ignored
workfold . -m fs --fs-exclude node_modules --fs-exclude '*.log'
```

Tracked files remain included even if a current ignore pattern matches them.
Explicit exclusions are applied after discovery and always win. When directory
entries are requested, the default ignore-respecting scan reports each ignored
subtree it prunes and states that descendant directories were not enumerated.
Use `--include-ignored` or the full profile when those entries and their
timestamps should be included.

An embedded Git repository inherits the containing scan's visibility decision
at its boundary. If the outer repository ignores that directory, the normal
scan prunes it; if it is visible, Workfold gives it an independent scan context
so its own ignore rules apply below the boundary. Naming the embedded
repository as an explicit `PATH` also scans it independently, even when a
separately selected parent repository ignores it.

## Choose an evidence preset

```bash
workfold . -p standard
workfold . -t all -m git -p portable
workfold . -t all -m both -p full
workfold . -t 2026-W31 -m fs -p full
```

`-p/--profile` selects an evidence preset and defaults to `standard`. Presets
answer different questions about the available evidence; they are not merely
levels of collection depth.

### Standard: What does the ordinary activity pattern look like?

The standard profile is the customizable everyday view:

- Git mode uses commit records and their author dates from local branches plus
  a detached `HEAD`.
- Filesystem mode uses birth and modification dates for regular files while
  respecting Git ignore rules.
- Combined mode applies both sets of defaults.

Use `--events` instead of the mode/profile pair when these event defaults are
not the desired combination. Standard keeps the initial chart focused, but it
is not a completeness claim.

### Portable: What dated evidence is stored inside Git objects?

A commit stores two independently meaningful clocks:

- the **author date**, describing when the change was originally authored;
- the **committer date**, describing when that particular commit object was
  created or rewritten.

An annotated tag is a separate Git object with a **tagger date**, describing
when that tag object was created. For example:

```text
Monday 10:00    Alice originally authors a commit    → author date
Thursday 15:00  Bob rebases or cherry-picks it       → committer date
Friday 09:00    Bob creates annotated tag v1.0       → tagger date
```

Standard shows the Monday author event. Portable retains all three object-backed
observations. If one commit's author and committer timestamps are identical,
Workfold may plot one marker carrying both roles; provenance and coverage still
retain both timestamp roles.

Portable is a locked, Git-only profile. It reads commit author and committer
dates from all locally stored refs plus annotated-tag tagger dates. Lightweight
tags have no independent tag object or tagger date and remain explicitly
unavailable. Derived per-file changes are excluded because Git does not store a
separate timestamp for each changed file.

These timestamps travel when their Git objects are transferred, but they do
not say when an object was pushed or published. Portable therefore excludes
local reflogs and filesystem metadata, and Workfold never invents push,
branch-creation, or lightweight-tag creation times.

### Full: What dated evidence can this local machine still discover?

Full selects every supported evidence kind available to the selected mode. In
Git mode it enables commit, file-change, tag, and reflog records, both commit
times, and all locally stored refs. In filesystem mode it enables every
supported timestamp and entry kind and includes ignored entries.

Full includes machine-local and mutable evidence, so it is broader than
portable rather than more transferable. It changes collection scope only and
does not enable the detailed coverage ledger automatically.

Profiles never change the selected time or mode: `full` does not imply
`-t all` or `-m both`. `--events` is an alternative to profiles, not an
override layered on top of one. Portable and full lock their reachability and
ignore-policy defaults; `--git-identity` and, when filesystem mode is
enabled, repeatable `--fs-exclude` may still narrow them. Such
narrowing remains visible in coverage status and verbose output.

## Control terminal detail

```bash
workfold . --cluster-window 1m30s --cluster-anchor event
workfold . --cluster-window 10m
workfold . --cluster-window 1h
workfold . --cluster-window 1h5m --cluster-anchor midnight
workfold . --cluster-window '1h 5m'
workfold . --band-label start
workfold . --cluster-anchor midnight --show-empty-bands
workfold . --hours all
workfold . --marker-style identity
workfold . --grid both
workfold . --hide-empty-days all
workfold . --hide-days weekend
workfold . --color
workfold . --no-color
NO_COLOR=1 workfold .
workfold . --list all --limit 50
workfold . --list outside
workfold . --events git:tag:tagger fs:file:accessed --list git:tag:tagger fs:file:accessed
workfold . --events git:tag:tagger fs:file:accessed --list outside git:tag:tagger fs:file:accessed
workfold . --coverage
workfold . --strict
workfold . --verbose
```

Color is automatic by default and is emitted only for a capable terminal.
`NO_COLOR` and `--no-color` disable it. `--color` restores automatic color when
a configuration file sets `no-color = true`; it still respects `NO_COLOR`,
terminal capability detection, and output redirection.

With the default source markers, every output keeps circle/square for
Git/filesystem and filled/hollow for inside/outside hours. In identity-marker
mode, single identities use uppercase/lowercase for inside/outside, while
composite identities use `◆`/`◇`. Color reinforces these forms rather than
replacing them. Identity mappings themselves remain independent of schedule
state: each canonical code and full recorded identity appears once in the key.

`--verbose` appends operational details after the compact summary: cluster and
compression policy, Scope (mode plus profile), Period (range plus timezone), the
full Coverage status, source/record breakdowns, exact Git/filesystem collector
selection, Git identity scope, resolved repositories/roots, and filesystem
ignore/exclusion policy. It does not change the matrix, compact totals, or
coverage result, and it also appends the detailed accounting ledger.
`--coverage` prints that same ledger without the verbose context/operational
block. Neither output flag changes collection scope, and the `full` profile
enables neither one implicitly.

`-l/--list` appends exact event details after the report. `all`, `inside`, and
`outside` select schedule state; event identifiers and wildcards select event
kinds. Several event selectors form a union, while a schedule selector
intersects that union. Thus `--list outside git:tag:tagger fs:file:accessed` means
“outside-hours events that are either tag or access-time evidence.” The event
kinds must already be enabled in the report; a list wildcard matches only the
enabled scope and must match at least one kind. The list never broadens
collection implicitly. `--list none` disables a list inherited from
configuration.

The list keeps the newest `--limit` matching markers (default 50), renders them
in chronological order, and reports how many additional matches were omitted.
It does not alter the matrix, totals, or coverage. Exact timestamps retain
offsets and nanoseconds where available; the list identifies each marker's
canonical event kind, schedule classification, repository/root, and source
detail, including an abbreviated commit ID or ref when present. A fixed
inside/outside selection states that classification once in the heading; an
all-schedule list shows it per row.

`--strict` returns a non-zero status for partial traversal, parsing, or
permission failures instead of accepting a useful-but-partial report.
Unsupported platform capabilities remain visible and are never replaced with
invented timestamps.
